# Chapter 5 Exercises — Managing the Test Activities
*20 questions, closed book. Target ≥ 80% (16/20). Answers: [`../answer-explanations/chapter-05-answers.md`](../answer-explanations/chapter-05-answers.md).*

**1.** Which of the following is a MEASURABLE exit criterion?
a) "The system feels stable"
b) "95% of planned test cases executed, no open critical defects"
c) "Testing has gone on long enough"
d) "The team is confident"

**2.** Entry criteria for test execution primarily prevent:
a) Excessive documentation
b) Starting execution too early, wasting effort on untestable builds
c) Stakeholder involvement
d) Test automation

**3.** A team estimates test effort using defect counts and velocity from previous releases. This is:
a) Expert-based estimation
b) Metrics-based estimation
c) Defect-based analysis
d) Risk-based estimation

**4.** "Planning poker" used to size testing tasks is:
a) Metrics-based estimation
b) Expert-based estimation
c) A risk analysis technique
d) A review type

**5.** The test pyramid recommends:
a) Many end-to-end tests, few component tests
b) Many fast component tests at the base, fewer integration and few end-to-end tests above
c) Equal numbers at every level
d) Manual testing only at the top

**6.** Performance and security testing belong to which test quadrant?
a) Q1 technology-facing, supporting the team
b) Q2 business-facing, supporting the team
c) Q3 business-facing, critiquing the product
d) Q4 technology-facing, critiquing the product

**7.** Risk level is calculated as:
a) Impact ÷ likelihood
b) Likelihood × impact
c) Likelihood + impact
d) Impact − likelihood

**8.** Feature A: likelihood 3, impact 2. Feature B: likelihood 1, impact 9. Which justifies MORE test effort under risk-based testing?
a) A (risk level 6)
b) B (risk level 9)
c) Equal effort
d) Neither — risk never changes effort

**9.** "Customer credit card data could be exposed by a weak payment module." This is a:
a) Project risk
b) Product risk
c) Testing risk
d) Schedule risk

**10.** "The test tool vendor may withdraw support mid-project." This is a:
a) Product risk
b) Project risk
c) Defect
d) Failure

**11.** Risk-based testing reduces:
a) All risk to zero
b) The level of risk by mitigating the highest risks first; remaining risk is residual and communicated
c) Only project risks
d) The need for exit criteria

**12.** Comparing actual test progress against the plan and re-prioritising tests when behind schedule are, respectively:
a) Monitoring; control
b) Control; monitoring
c) Estimation; completion
d) Analysis; design

**13.** A report for senior management should be:
a) Every test case with full steps
b) A concise summary of cost, schedule, quality and risk
c) Raw log files
d) A list of every defect comment thread

**14.** Which metric helps decide whether testing can stop?
a) Defect find/fix trend and open-defect counts against exit criteria
b) Number of coffee breaks
c) Lines of code written
d) Number of meetings held

**15.** Test completion activities include all EXCEPT:
a) Checking exit criteria fulfilment
b) Writing a test completion report with lessons learned
c) Archiving testware
d) Starting a brand-new test project to delay release

**16.** Configuration management of testware ensures:
a) Tests always run faster
b) The right versions of testware match the right product versions and results are reproducible
c) Defects are fixed faster
d) Tools never need updates

**17.** In the defect lifecycle, the state after "Fixed" is typically:
a) Closed immediately
b) Awaiting confirmation test (re-test); then Closed if it passes, Reopened if it fails
c) New
d) Rejected

**18.** Which set of elements makes a defect report USABLE?
a) Blame, opinions, and vague symptoms
b) Unique ID, steps to reproduce, expected vs. actual result, environment/build, severity
c) Only the tester's name
d) Only the fix description

**19.** A minor cosmetic typo on the company homepage one day before a major public launch is likely:
a) High severity, high priority
b) Low severity, high priority
c) High severity, low priority
d) Low severity, low priority

**20.** Residual risk means:
a) Risk that testing eliminated
b) The risk remaining after mitigation, which stakeholders must accept or address
c) Only hardware risks
d) Risks in the test plan template
