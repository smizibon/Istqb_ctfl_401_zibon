# Chapter 6 Exercises — Test Tools
*12 questions, closed book. Target ≥ 80% (10/12). Answers: [`../answer-explanations/chapter-06-answers.md`](../answer-explanations/chapter-06-answers.md).*

**1.** A tool that plans, stores and traces test cases and defects belongs to:
a) Test management tools
b) Static analysis tools
c) Test execution tools
d) Support tools

**2.** A tool simulating 10,000 concurrent users to measure response time is:
a) A test management tool
b) A non-functional testing tool (performance)
c) A static analysis tool
d) A test design tool

**3.** A compiler is an example of:
a) Test execution tooling
b) Static analysis tooling
c) Non-functional testing tooling
d) Configuration management

**4.** A CI/CD pipeline and version control system are classified as:
a) Support tools
b) Test design tools
c) Static analysis tools
d) Non-functional tools

**5.** A tool that generates test data matching production-like patterns is:
a) Test design/implementation support tool
b) Test management tool
c) Incident management tool
d) Performance tool

**6.** Which is a genuine benefit of test execution tools?
a) They guarantee defect-free releases
b) Faster, repeatable regression runs with consistent comparison of results
c) They remove the need for test planning
d) They replace tester judgement

**7.** An unrealistic expectation of a test tool is:
a) "It will speed up nightly regression"
b) "It will find all defects automatically and improve quality by itself"
c) "It will require training"
d) "It will need maintenance"

**8.** Which is a documented RISK of tool support?
a) Consistent test execution
b) Underestimating the time, cost and effort of introduction and maintenance
c) Faster feedback
d) Better coverage assessment

**9.** Before organisation-wide rollout, the team uses a new test automation tool on one small project to check fit and learn the real cost. This is:
a) A pilot project
b) A walkthrough
c) A retrospective
d) Static analysis

**10.** Vendor lock-in and loss of vendor support are risks relating to:
a) Test design
b) Tool dependency/vendor dependence
c) Test monitoring
d) Traceability

**11.** Test automation code that is never updated after application changes leads to:
a) Improved maintainability
b) False confidence and decaying, failing suites (maintenance neglect)
c) Better metrics
d) No consequence

**12.** Which tool directly supports the test *monitoring and control* activity?
a) A dashboard visualising planned vs. executed tests and defect trends
b) A code linter
c) A data generator
d) A load generator
