# Chapter 3 Exercises — Static Testing
*15 questions, closed book. Target ≥ 80% (12/15). Answers: [`../answer-explanations/chapter-03-answers.md`](../answer-explanations/chapter-03-answers.md).*

**1.** Static testing differs from dynamic testing because static testing:
a) Requires executable code
b) Examines work products without executing them
c) Only finds failures
d) Is always automated

**2.** Which finding is typical for static testing of a *requirements document*?
a) A runtime crash when saving
b) An ambiguous requirement that can be interpreted two ways
c) A slow database query
d) A memory leak under load

**3.** A tool reports an unused variable and an unreachable branch without running the program. This is:
a) Dynamic testing
b) A review
c) Static analysis
d) Debugging

**4.** Which of these is a static analysis tool?
a) Load generator
b) Compiler
c) Capture/replay tool
d) Test management platform

**5.** Static analysis can find defects that dynamic testing cannot because it:
a) Executes more test cases
b) Examines structure (e.g., unreachable code) that may never be executed at runtime
c) Uses faster hardware
d) Is done by more experienced testers

**6.** In a review, the person who collects comments and defects raised during the meeting is the:
a) Author
b) Facilitator
c) Scribe
d) Manager

**7.** The review role responsible for the review's overall success, including planning and follow-up, is the:
a) Review leader
b) Scribe
c) Moderator only
d) Reviewer

**8.** Who decides whether a review is performed at all, and its objectives?
a) Scribe
b) Manager
c) Author
d) Reviewer

**9.** A review led by the author to explain the design to the team and gather comments is a:
a) Walkthrough
b) Inspection
c) Technical review
d) Audit

**10.** The most formal review type, with rules, checklists, metrics, entry/exit criteria and a trained moderator who is not the author, is:
a) Informal review
b) Walkthrough
c) Technical review
d) Inspection

**11.** Pair reviewing a colleague's test cases at their desk, no documents, no formal roles — this is:
a) An inspection
b) An informal review
c) A technical review
d) Static analysis

**12.** Which is a typical objective of a technical review?
a) Author education only
b) Reaching consensus, detecting defects, and evaluating alternatives among technical peers
c) Releasing the product
d) Performance measurement

**13.** Which statement about reviews is TRUE?
a) Reviews always require a formal meeting
b) Reviews only find defects in code
c) Reviews can spread knowledge and improve consistency of work products
d) Reviews replace dynamic testing

**14.** A review descends into personal blame and the author becomes defensive. Which success factor was violated?
a) Review rate limits
b) A blame-free, defect-focused culture
c) Use of checklists
d) Entry criteria

**15.** To keep reviews effective, work products should be reviewed:
a) In one long end-of-project session
b) In small chunks respecting limited review rates (pages per hour)
c) Only by managers
d) Only after release
