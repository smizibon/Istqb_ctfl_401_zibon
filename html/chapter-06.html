6.1 The six tool categories

K2

Name the category from the description — traps: performance = non-functional, Git = support, a compiler = static analysis.

In plain words: six labelled boxes — match each tool to its box.

📖 Memorise — with examples (exam gives a description, you name the category)
Test managementplan, store, trace, report tests & defectstest management platforms, defect trackers
Static analysisexamine code/models without executioncompilers, linters, security analysers
Test design / implementationgenerate tests & data from models/specsmodel-based generators, test-data generators
Test execution & automationrun tests, compare results, drive GUI/APIcapture/replay frameworks, API runners
Non-functional testingmeasure quality characteristicsperformance/load tools, security scanners
Support toolskeep test work efficient & manageableCI/CD, build tools, version control, incident management, spreadsheets
⚠️ Top traps • Performance tools are non-functional tools — not “test execution” tools.
• Version control is a support/configuration-management tool — not test management.
• A compiler is a static analysis tool.

6.1.2 — tools can support every test activity: planning (scheduling), monitoring/control (dashboards), analysis (coverage of conditions), design (generators), implementation (data, environments), execution (automation, CI), completion (reports), incident logging. One tool may serve several activities; tools range from spreadsheets to frameworks.

In plain words: tools can assist every test activity — planning through reporting — not just running tests.

বর্ণনা শুনে category-র নাম বলতে হবে — ফাঁদ: performance মানে non-functional, Git মানে support, আর compiler মানে static analysis।

৬.১.২ — tool প্রতিটি test activity-কেই সাহায্য করতে পারে: planning (scheduling), monitoring/control (dashboard), analysis (condition-এর coverage), design (generator), implementation (data, environment), execution (automation, CI), completion (রিপোর্ট), incident logging। একটা দিয়েই একাধিক activity চলতে পারে; spreadsheet থেকে framework পর্যন্ত সবই tool।

6.2 Benefits · risks · pilot projects

K2

Benefits from automating repetition — tools help, never guarantee; know the risk list; try one small pilot before rollout.

In plain words: why tools pay off, how they backfire, and test small first.

🧠 Understand — the benefit pattern Benefits come from automating repetitive work: time savings, fewer human errors, consistency & repeatability, better coverage assessment, faster feedback — enabling what manual testing can’t do economically (nightly regression of thousands of tests).

⚠️ The exam’s favourite true/false: a tool helps but never guarantees — it cannot replace tester skill/judgement, and benefits only materialise with proper introduction, trained people, and a purpose that fits the context.
📖 Memorise — the risk list • Unrealistic expectations (expecting the tool to fix a broken process)
• Underestimated time, cost, effort of introduction and ongoing maintenance
• Over-reliance / neglect of human judgement
• Vendor dependency (support, licensing, lock-in)
• Version-control neglect of test assets
• Tool less reliable than the product (false confidence)
✏️ Pilot project — the go/no-go mechanism Before organisation-wide rollout, run the tool on one small, contained project: does it fit our context and needs? What does it really cost (effort, training, maintenance)? Decide with realistic expectations before full investment. Scenario “team tries the tool on one project first” → pilot project.

In plain words: pilot project = try the tool on one small job before committing.

Benefits আসে পুনরাবৃত্ত কাজ automate করা থেকে — tool সাহায্য করে, কখনো guarantee করে না; risk-এর লিস্টটা জেনে রাখো; পুরো rollout-এর আগে একটা ছোট pilot করে দেখো।

🧠 বুঝে নাও — benefits-এর প্যাটার্ন Benefits আসে পুনরাবৃত্ত কাজ automate করা থেকে: সময় বাঁচে, মানুষের ভুল কমে, consistency ও repeatability বাড়ে, coverage মূল্যায়ন ভালো হয়, feedback দ্রুত মেলে — এমন কাজও সম্ভব হয় যা হাতে-করা testing-এ অর্থনৈতিকভাবে করা যায় না (হাজারো test-এর nightly regression)।

⚠️ পরীক্ষার প্রিয় true/false: কোনো tool সাহায্য করে, কিন্তু কখনো guarantee করে না — এটা tester-এর দক্ষতা/বিচারবুদ্ধির বিকল্প নয়, আর benefits তখনই আসে যখন সঠিকভাবে পরিচয় করিয়ে দেওয়া হয়, মানুষকে প্রশিক্ষণ দেওয়া হয়, আর উদ্দেশ্যটা context-এর সঙ্গে মানানসই হয়।
📖 মুখস্থ করো — risk-এর লিস্ট • Unrealistic expectations (ভাঙা process আসলেই tool ঠিক করে দেবে ভেবে নেওয়া)
• পরিচয় করিয়ে দেওয়ার সময়, খরচ, শ্রম এবং চলমান maintenance-এর খরচ কম ভেবে নেওয়া
• অতিরিক্ত নির্ভরতা / মানুষের বিচারবুদ্ধিকে অবহেলা করা
• Vendor dependency (support, licensing, lock-in)
• test asset-এর version control-এর অবহেলা
• product-এর চেয়ে tool কম নির্ভরযোগ্য হওয়া (মিথ্যা আত্মবিশ্বাস)
✏️ Pilot project — go/no-go মেকানিজম পুরো সংস্থায় rollout করার আগে tool-টা একটা ছোট, সীমাবদ্ধ project-এ চালিয়ে দেখো: এটা কি আমাদের context ও প্রয়োজনের সঙ্গে মেলে? আসল খরচ কত (শ্রম, প্রশিক্ষণ, maintenance)? বাস্তবসম্মত প্রত্যাশা নিয়ে, পুরো বিনিয়োগের আগে সিদ্ধান্ত নাও। Scenario-তে "দল আগে একটা project-এ tool-টা চালিয়ে দেখে" → pilot project।

6 recall checks — say each answer aloud, then reveal.

1. Classify: JMeter, Git, SonarQube, a defect tracker.
JMeter = non-functional (performance) · Git = support/CM · SonarQube = static analysis · defect tracker = test management.
2. Three benefits of automation over manual regression?
Faster/repeatable runs; consistent result comparison; enables nightly full regression (any three from the pattern).
3. Three risks of introducing a test tool?
Unrealistic expectations; underestimated introduction+maintenance cost; vendor dependency; over-reliance (any three).
4. Pilot project — which two questions does it answer?
Does the tool fit our context/needs? What is its true cost of adoption and maintenance?
5. True/false: “A test management tool guarantees complete traceability.”
False — tools help, they never guarantee.
6. Which tool category supports nightly automated regression in CI?
Test execution & automation tools (running inside the CI/CD support pipeline).

Test execution & automation tool (CI/CD support pipeline-এর ভেতরে চেলে)।
